# W04 批判セッション（敵対的レビュー）

目的: 単独研究の構造的欠陥（外部批判者の不在）をAIで補償する（憲章第9条）。
入口: `/critique <対象ID>`。

## 手順
1. 対象（主張/概念/モデル）ファイルを critic サブエージェントに渡す
   - critic は独立コンテキストで動作し、プロジェクトへの「愛着」を持たない
2. critic は以下の観点で攻撃する:
   - 反証条件は本当に反証可能か（観察不可能な逃げ道がないか）
   - 対立説明で十分説明できてしまわないか
   - 既存研究の再記述ではないか
   - 証拠等級は過大評価されていないか
   - 概念定義の循環・曖昧性
3. 指摘を主張ファイル §7 に記録（都合の悪い指摘ほど省略しない）
4. 対応を決定: 改訂 / 限定 / 棄却 / 反論（反論する場合は根拠を記録）
5. 致命的指摘は refutations/ にも登録

## 頻度
- 主張の昇格前: 必須
- 支持済み主張: 半年に1回、または依存概念の改訂時に再実施
