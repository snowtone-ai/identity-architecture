# theory/ — 理論層の運用ルール

## 3つのサブディレクトリの役割

| ディレクトリ | 単位 | 真偽 | 例 |
|---|---|---|---|
| concepts/ | 概念 | 持たない | 「アイデンティティ・ギャップ」という概念 |
| claims/ | 主張 | 問える | 「ギャップの自覚は行動変化の頻度を高める」という主張 |
| models/ | モデル | 構成主張に依存 | 複数の支持された主張を統合した因果構造 |

## 運用規則
1. 新規ファイルは必ず `_TEMPLATE.md` をコピーして作成する
2. 作成と同時に同ディレクトリの `INDEX.md` に1行追記する（同一コミット）
3. 既存の「現行仮説」（Identity Discovery / Identity Gap / Identity Symbol / Identity Ritual / Identity Internalization / Behavioral Stabilization）は、概念ファイル化されるまで**仮説候補リスト**にすぎない。台帳に登録されていないものは理論の一部ではない
4. モデルの作成は、構成要素となる主張のうち過半が「支持（暫定）」になってから着手する（早すぎる体系化の禁止）

## 概念IDと主張IDの関係
- 主張ファイルは使用する概念IDを必ず参照する
- 概念が改訂された場合、その概念を参照する全主張を再点検する（auditor エージェントの月次業務）
